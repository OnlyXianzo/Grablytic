## Disagreements and limits resolved

- Older descriptions of the URL guard treated every DNS failure as fail-closed. The accepted policy is sink-specific: profile fetching is control-plane work and fails closed; media preflight does not reject user-selected content solely when resolution yields no answer. Direct media connections still require a current vetted public answer before connecting. Direct private/loopback/link-local/reserved literals and any resolved private answer are rejected.
- A DNS preflight alone left a time-of-check/time-of-use gap. The profile opener now connects to the exact validated sockaddr, disables ambient proxies, and validates/pins every redirect. Grablytic's yt-dlp wrapper likewise restricts the request director to its guarded urllib handler; direct HTTP(S) connections pin the vetted sockaddr and keep the original Host/TLS identity, and redirects receive the same validation. Optional network backends and non-HTTP redirect schemes are rejected rather than allowed to bypass the pin. Explicit user-configured HTTP/SOCKS proxies remain a trusted egress boundary because origin resolution happens in the proxy; this is the remaining rebinding limitation.
- The 256 KiB remote-profile and 1 MiB `.info.json` caps are local defensive policy choices, not upstream protocol limits. They are tested at the boundary and fail back without poisoning existing state.
- yt-dlp's remote EJS bundle is not passed through Grablytic's local JavaScript stub hash allowlist. The current PO-token stub is inert and disabled by default; the Deno deny-all flags apply to the local solver path only. The yt-dlp EJS bundle has its own upstream integrity mechanism, as documented in `engine/grablytic_engine/po_token.py`.

## Verified approach and blast radius

1. Treat a custom format expression as executable input. Reject `all`, `allvideo`, `allformats`, `mergeall`, malformed/control-containing expressions, overlong selectors, and unsupported containers at ingestion **and** at the direct options-builder boundary.
2. Bound remote profile bodies before JSON parsing; do not replace a good cache with empty, invalid, oversized, or failed responses. Write local profile updates through a same-directory temporary file, `fsync`, and `os.replace`.
3. For profile control-plane requests, resolve once per hop, reject every non-public answer, connect to one of the exact vetted socket addresses, preserve the original HTTP/TLS hostname, disable ambient proxies, revalidate every redirect, and cap the response body. For yt-dlp, use only the guarded urllib handler for direct HTTP(S), pin each redirect hop, and preserve Host/TLS identity. Keep the sink-specific media preflight policy; the actual direct connection still requires a vetted public answer. Explicit user-configured proxies remain trusted egress boundaries.
4. Enforce bounded work at each layer: 4 MiB IPC line ceiling, 8 slow-lane workers, 24 in-flight slow requests, `ERROR_BUSY` load shedding, 4 watchdog workers with a queue capped at 500, five retry-backoff permits, and bounded progress/result queues.
5. Do not use `Queue.empty()` to decide whether the client received a terminal result. Mark delivery only when a callback returns successfully or a result is drained; if the callback fails, fall back to the result queue. Check the slot-generation token before marking, and retain the 30-second cleanup failsafe.
6. Install and verify one FFmpeg serialization seam (primary `real_run_ffmpeg`, fallback `Popen.run`). If neither can be verified, reject the download instead of silently running post-processing without the concurrency bound.
7. Blast radius: `site_profiles.py`, `url_guard.py`, `ytdlp_network.py`, `format_selector.py`, `opts_builder.py`, `resume.py`, `downloader.py`, `formats.py`, `playlist.py`, `search.py`, `__main__.py`, the yt-dlp minimum-version declaration, and their focused pytest modules.
