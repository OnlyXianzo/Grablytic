## Disagreements resolved

Older Flutter integration examples use `flutter_driver` or direct Gradle instrumentation commands. The current official Flutter guide documents `integration_test` for physical devices and emulators, so the smoke test uses that supported path. Coverage guidance distinguishes executable-but-untested source from non-runnable code: a poorly covered production module is not “dead code.” Therefore the configuration documents narrow non-runnable block exclusions and does not remove a production file from the denominator. Confidence: **High**.

## Verified approach / blast radius

1. Add an Android emulator integration test which instantiates the production Dart `PlatformChannelEngineService`, calls `paths/set`, `engine/bootstrap`, and `download/queue_status`, and asserts the Python contract payload. Use Android `sqflite` in the same test to verify FTS4 indexing and token search on system SQLite.
2. In CI, run only the emulator's `x86_64` ABI and skip native package downloads for this smoke test. Do not bypass Python packaging, MainActivity setup, MethodChannel dispatch, Chaquopy initialization, or Python return serialization.
3. Configure narrow Python coverage exclusions for unreachable typing-only and module-entrypoint blocks; keep all production engine modules in `--cov` scope.
4. Enforce a 30% Flutter line-coverage floor with a dependency-free LCOV parser. Count unique `DA` lines for project `lib/` sources and check `LF`/`LH` summaries; no external `lcov` binary is required. This floor applies only to the source records emitted by Flutter's test coverage run.
5. Blast radius: `pubspec.yaml`/lockfile, `integration_test/`, `tool/check_flutter_coverage.py`, `.github/workflows/verify.yml`, `.coveragerc`, `.deepsource.toml`, and the CI verification documentation. Android service/package changes are compiled by the same Android integration build.
6. Prove: validate Flutter analysis and targeted unit tests locally; test the LCOV parser with passing/failing fixtures; parse workflow YAML; run the full Python suite with coverage locally; run the Android emulator test in CI (local workspace has no Android SDK/emulator). A local full Flutter coverage run was stopped after 12 minutes (508 tests, no final report), so its result remains unverified and CI is authoritative for the 30% gate.
