## Disagreement resolved

Some secondary articles say FTS5 is available on Android API 24+, while other sources and real platform builds report that the system SQLite may omit it. The key distinction is **SQLite version versus the system build's compile flags**. SQLite's own docs and AOSP's platform build flags confirm that FTS modules are compile-time optional and that FTS5 is separately enabled. Since this app uses Android's system SQLite via `sqflite` and does not bundle SQLite, FTS4 is the portable choice. The SQLite docs also warn that external-content FTS4 triggers must delete before content updates and split update triggers across before/after phases. To reduce trigger-ordering risk, the implementation uses a normal FTS4 virtual table containing duplicate title/URL text, with straightforward insert/update/delete triggers and a one-time `INSERT ... SELECT` backfill. A Python SQLite FTS4 probe verified the trigger lifecycle and backfill SQL. Confidence: **High**.

## Verified approach / blast radius

1. Remove the top-level `proxy` (and nested proxy credential fields) from every history config before `configJson` is written. Scrub already persisted `configJson` rows on the next DB schema migration. Restore a proxy for a resumed download only from the secure settings provider; never restore it from SQLite.
2. Move `SettingsNotifier` proxy reads/writes to `flutter_secure_storage`; migrate legacy SharedPreferences data and delete the old key. The plugin's Kotlin Android implementation supplies Keystore-backed encryption. Do not add a Kotlin plaintext preference path.
3. Bump the database version for the config scrub, then independently for FTS4. Add an ordinary FTS4 table plus insert/update/delete triggers, backfill with `INSERT ... SELECT`, and use an indexed `MATCH` join for title/URL search. Keep status filters, ordering, pagination, and non-search queries intact.
4. Test: legacy-proxy migration and no plaintext preference writes; history JSON and old-row scrub; interrupted-download recovery obtains proxy from secure storage; fresh FTS search, update/delete trigger sync, stale-index LIKE fallback, and v4/v5 migration backfill. The Android emulator smoke test also requires the system SQLite FTS4 path and verifies a real token match; host FFI builds without FTS4 exercise the fallback.

**Blast radius:** `settings_provider.dart`, `download_config.dart` (settings→engine config), `download_provider.dart` (history write + auto-resume), `download_history_db.dart` (schema + search), settings/download-provider tests, `pubspec.yaml`/lockfile, plus Android plugin registration/build through Flutter's generated plugin registry. `android/app/src/main/AndroidManifest.xml` already has `allowBackup=false`; keep it that way.
